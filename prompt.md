# SCOPE (build in this priority order, finish each before moving on)

## Module 1: Synthetic data generator (P2 foundation)
- Script that generates ~50 plots and ~100 deeds with realistic Bangla fields: dummy owner names in Bangla, father's name, mouza, upazila, district, khatian number, dag/plot number, area (decimal/shotok), survey type (CS/SA/RS/BS), deed number, registration date, sub-registry office.
- Include a few deliberate demo scenarios: (a) a clean ownership chain, (b) a plot sold twice by the same seller, (c) a rapid chain of transfers within days, (d) a plot flagged as khas/acquired, (e) a plot with a pending case, (f) a registered deed with no matching mutation.
- Use fixed random seed so demos are reproducible.

## Module 2: Tamper-evident registry (core)
- Canonicalize deed content (sorted keys, Unicode NFC normalization for Bangla text, fixed number formatting) before hashing, so the same deed always yields the same hash.
- Hash with SHA-256. Sign the hash with an Ed25519 key representing the sub-registry office. Generate keys for the demo and store them outside the repo; document that production would use an HSM or KMS.
- Append each registered deed to a hash-chained ledger: each entry stores deed_id, deed_hash, signature, timestamp, prev_entry_hash, entry_hash. Do NOT call this a blockchain; describe it honestly as a hash-chained append-only log.
- Ledger integrity check: a function and endpoint that walks the chain and reports the first broken link if any entry was edited.
- Storage: SQLite.

## Module 3: QR-stamped deeds and verification (the main demo moment)
- On registration, generate a printable deed (HTML or PDF) with Bangla text rendered correctly (use Noto Sans Bengali or similar) and a QR code that encodes a verification URL containing deed_id and the deed hash.
- Verification page (mobile-friendly): scan QR or enter deed ID, and optionally enter or upload the deed's fields, then recompute the hash and compare against the ledger and signature. Result must be one of: AUTHENTIC (green), ALTERED (red, show which fields differ), NOT FOUND (grey).
- Include a clearly labelled "Tamper demo" mode or sample page that lets us change one digit of a deed and re-verify, to show ALTERED live.

## Module 4: Double-sale and fraud flags (P3, rule-based)
- On every new registration attempt, check the plot against the ledger and return flags:
  - SAME_SELLER_RESOLD: the same seller already transferred this plot or share
  - OVER_SOLD_AREA: total transferred area exceeds the plot's area
  - RAPID_TRANSFER: more than N transfers within M days (configurable)
  - NO_MUTATION: registered deed with no mutation record after X days (simulated)
- Rule-based only. No machine learning. Show a short human-readable reason for each flag in Bangla and English.
- Officer dashboard page listing flagged deeds with the reason.

## Module 5: Citizen "Check Before You Buy" report (P5)
- Input: plot ID. Output: a green/yellow/red Plot Safety Report with: ownership chain timeline, mutation status (simulated), pending cases (simulated), khas/acquisition flag (simulated), and any fraud flags from Module 4.
- Plain-language summary in Bangla with an English toggle. Add a clear note that data is DUMMY.

## Module 6 (only if time remains): Simple mutation tracker
- When a deed is registered, auto-create a simulated mutation case with status steps (Submitted, Under review, Approved) so the registration-to-mutation link is visible in the UI.
